TwinNU Website Technical Setup & Architecture

This document outlines the core technical decisions, required dependencies, and project structure necessary for a seamless and scalable development of the TwinNU website using modern React best practices.I. Tech Stack Summary

The website will be built on a high-performance, cutting-edge stack to ensure speed, scalability, and an excellent developer experience.
Area
Technology / Choice
Rationale
Framework
Next.js 14+ (App Router)
Enables superior performance, SEO optimization via SSR/SSG, and provides a modern routing and data-fetching layer.
Language
TypeScript
Essential for maintaining a scalable, error-free codebase and improving developer productivity across the team.
Styling
Tailwind CSS (Utility-First)
Allows for rapid, precise, and custom styling that perfectly achieves the minimalist, aesthetic feel without heavy CSS-in-JS libraries.
Components
Shadcn/ui (Built on Radix UI)
Provides fully functional, accessible, and unstyled primitives that can be customized with Tailwind, ensuring component reusability and maximum control over the final aesthetic.
Animation
Framer Motion
The declarative standard for complex, smooth, and performant animations (e.g., text glide-in, on-scroll feature reveals).
Theming
`next-themes`
Simple, effective solution for implementing the dark/light mode toggle with theme persistence.

V. Component Reusability & State

To ensure the website is easy to adapt and scale (e.g., adding a new feature card or updating the Twiniverse package plan), we rely heavily on the following pattern:
Reusability with cva: Use the `class-variance-authority` (`cva`) package to define component appearance variants.
Example: A single <Button> component can accept a variant="primary" (Neon Accent), variant="secondary" (Ghost/White), and variant="placeholder" (Greyed Out) prop, making the "COMING SOON" elements simple to manage.
Consistency with Shadcn/ui: All basic UI elements (Cards, Dialogs, etc.) should originate from a Shadcn/ui blueprint to guarantee accessibility and a consistent base structure, with Tailwind customizing the final look (e.g., adding the Frosted Glass effect).
Theme Integration: All color utilities must reference the Tailwind config, which is dynamically controlled by `next-themes` and the global theme state. This ensures that the Frosted Glass element's blur color shifts correctly when the user toggles modes.
